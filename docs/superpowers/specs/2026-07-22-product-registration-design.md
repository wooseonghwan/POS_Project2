# 상품 등록/수정 화면 설계

## 배경

재고관리(`InventoryView`)는 현재 조회 + 삭제만 지원한다. 원본 디자인(`Fishing Mart POS.html`)에는 재고관리와 짝을 이루는 "상품등록" 화면이 있었고(사진, 대/소/POS분류 인라인 코드관리, 상품명, 바코드 자동생성, 단가, 초기재고), 사용자가 재고관리에 등록/수정 기능이 없다는 점을 지적하면서 이번 작업이 시작되었다.

## 목표

- 재고관리에서 신규 상품을 등록하고, 기존 상품 정보를 수정할 수 있다.
- 대분류/소분류/POS분류 코드를 폼 안에서 바로 추가/삭제할 수 있다(인라인 코드관리).
- 상품 사진을 실제로 업로드해서 재고관리 목록에 표시할 수 있다.
- 바코드를 비워두면 기존 채번 규칙을 이어서 자동 생성한다.

## 아키텍처

**등록/수정 통합 화면** 하나(`InventoryFormView` + `InventoryFormViewModel`)를 새로 만든다. "등록"과 "수정"은 같은 폼을 재사용하며, 진입 시점에 편집 대상 상품이 있는지(barcode 유무)로 모드를 구분한다.

- 재고관리(`InventoryView`) 헤더에 "+ 상품등록" 버튼 추가 → 빈 폼으로 `InventoryFormViewModel` 진입 (등록 모드)
- 재고관리 각 행에 "수정" 버튼 추가(기존 "삭제" 옆) → 해당 행의 상품 데이터로 폼을 채워 진입 (수정 모드)
- 저장 완료 시 재고관리로 돌아가고 목록을 새로고침한다.

## 폼 구성 (원본 디자인 순서 그대로)

1. **상품 사진** — 미리보기 + "사진 선택" 버튼
2. **대분류** 드롭다운 + "코드관리" 토글
3. **소분류** 드롭다운 + "코드관리" 토글
4. **POS분류** 드롭다운 + "코드관리" 토글
5. **상품명** (필수)
6. **바코드 번호** (공란 허용 → 자동 생성)
7. **단가** (필수, 양수)
8. **초기재고** (공란 시 0) — 수정 모드에서는 "재고" 라벨로 표시하되 재고 수량 자체는 이 화면에서 직접 조정 가능하게 둔다(별도 재고조정 기능은 범위 밖)
9. **등록하기 / 저장하기** 버튼 (모드에 따라 라벨 다름)

## 코드관리 (대/소/POS분류 인라인 추가·삭제)

각 드롭다운 옆 "코드관리" 토글을 누르면 패널이 펼쳐진다:
- 기존 코드 목록(이름 + 코드) 각 항목 옆에 "삭제" 버튼
- 하단에 코드/이름 입력창 2개 + "추가" 버튼

`ICodeRepository`에 메서드 추가:
- `Task AddAsync(string codeGbn, string codeCd, string codeNm)`
- `Task DeleteAsync(string codeGbn, string codeCd)` — 이미 `product_tb`에서 사용 중인 코드(major_cd/minor_cd/poscat_cd)면 삭제하지 않고 "사용 중인 코드는 삭제할 수 없습니다" 에러를 반환한다(DB에 FK 제약은 없으므로 앱단에서 `IProductRepository`를 통해 사용 여부를 확인).

## 사진 업로드

- "사진 선택" 클릭 → `Microsoft.Win32.OpenFileDialog` (필터: jpg/png)
- 선택 즉시 폼 내 `Image` 컨트롤에 미리보기
- 저장 시 앱 실행 폴더 하위 `ProductPhotos/{바코드}.{원본 확장자}`로 파일을 복사하고, `product_tb.photo_path`에 상대 경로(`ProductPhotos/8800000020050.jpg` 형식)를 저장한다.
- 바코드가 자동 생성되는 등록 케이스에서는 저장 직전에 바코드를 확정한 뒤 파일명에 사용한다.
- 재고관리 목록: `photo_path`가 있으면 실제 사진을 표시하고, 없으면 기존 스와치+이니셜 블록으로 폴백한다(기존 시드 상품 47개는 사진이 없으므로 폴백이 항상 필요).
- **판매 화면(POS) 상품 타일은 이번 범위에서 변경하지 않는다** — 원본 디자인도 여기는 스와치+이니셜만 쓰고 실제 사진을 쓰지 않으므로 그대로 유지.

## 바코드 자동 생성

기존 데이터가 `8800000002` 접두사 + 4자리 일련번호(`0001`~) 패턴이므로, 바코드 입력이 비어 있으면:
1. 해당 접두사로 시작하는 기존 바코드 중 마지막 4자리의 최댓값을 조회
2. 그 값 + 1을 4자리 0-padding해서 접두사에 붙인다 (예: 최댓값이 `...0050`이면 다음은 `...0051`)

새 리포지토리 메서드를 추가하지 않고, 이미 있는 `IProductRepository.GetActiveAsync()`로 불러온 전체 상품의 barcode를 클라이언트 쪽에서 필터링(`8800000002`로 시작하는 것만)해 마지막 4자리를 파싱, 최댓값 + 1을 계산한다. 상품 수가 많지 않은 소매점 규모라 전체 조회 방식으로 충분하다.

## 검증 규칙

- 상품명: 필수 (공란 저장 불가)
- 단가: 필수, 0보다 커야 함
- 초기재고/재고: 공란이면 0으로 처리
- 바코드: 등록 모드에서 사용자가 직접 입력한 값이 이미 `product_tb`에 존재하면 "이미 등록된 바코드입니다" 에러(자동 생성된 값은 항상 유일하므로 이 검증은 사용자가 수동 입력했을 때만 해당)
- 저장 버튼은 항상 활성 상태로 두고, 클릭 시 검증에 실패하면 `LoginView`의 로그인 실패 카드와 같은 스타일(`ErrorBorder`/`ErrorIconBackground`)의 에러 메시지를 폼 상단에 표시한다(모달이 아니라 폼 내 인라인 배너)

## 데이터 흐름 요약

```
InventoryView (+ 상품등록 / 수정 버튼)
    → InventoryFormViewModel.Load(barcode?: string)
        - barcode 없음 → 빈 폼 (등록 모드)
        - barcode 있음 → IProductRepository에서 상품 조회 후 폼 채움 (수정 모드)
    → 사용자 입력 (+ 코드관리 추가/삭제 + 사진 선택)
    → 저장
        - 검증
        - 사진 있으면 파일 복사 + photo_path 계산
        - 바코드 공란이면 자동 생성
        - IProductRepository.SaveAsync(product) (insert or update)
    → 재고관리로 복귀 + 목록 새로고침
```

## 범위 밖

- 재고 수량의 별도 입출고 이력 관리(단순 필드 수정만 지원)
- 사진 크기 제한/압축/리사이즈
- 상품 삭제 확인 모달 변경(기존 그대로 유지)
- 판매 화면 상품 타일 디자인 변경

## 테스트 계획

`InventoryFormViewModelTests` (TDD, 아래 각각 실패 테스트 먼저 작성):
- 등록 모드 진입 시 폼이 비어 있음
- 수정 모드 진입 시 기존 상품 값으로 폼이 채워짐
- 상품명 없이 저장 시도 → 에러, 저장 안 됨
- 단가 없거나 0 이하로 저장 시도 → 에러
- 바코드 공란으로 등록 → 기존 접두사 패턴 이어서 자동 생성됨
- 바코드 수동 입력이 중복 → 에러
- 코드관리에서 코드 추가 → 드롭다운에 즉시 반영
- 코드관리에서 사용 중인 코드 삭제 시도 → 거부 + 에러 메시지
- 코드관리에서 미사용 코드 삭제 → 목록에서 제거됨
- 사진 선택 후 저장 → `photo_path`가 올바른 파일명으로 저장됨
